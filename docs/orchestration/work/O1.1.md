## Criterios de aceptación

| Acción | Resultado esperado |
|---|---|
| Instalar los hooks en el clon | Existe `.git/hooks/pre-commit` |
| Commit de un token falso en una rama desechable, sin push | El commit falla por gitleaks; el token no entra al historial ni a la salida guardada |
| Borrar la rama desechable | La rama no existe y nunca llegó a GitHub |
| Commit normal en la copia aparte | Los hooks corren y pasan |
| Juan revisa la regla de `main` en GitHub | Queda registrado si exige PR, si exige checks, si bloquea force push y si admite excepciones |
| Sesión nueva en modo plan, con una línea que apunte a este archivo | Responde igual que esta especificación y `git status` queda vacío |
| Buscar rutas personales y secretos en el diff | Sin rutas `C:\Users\` nuevas, y gitleaks en verde |
| Push de la rama y clic en el enlace del PR | Los checks de CI en verde |
| Juan hace merge de los dos PR | `main` contiene el contrato y ambos cierres |
| Estado final | `main` limpio y sincronizado |

## Riesgos

| Riesgo | Mitigación |
|---|---|
| La auditoría pública describe debilidades | Se publica con el hook ya activo y sin rutas personales; Juan lee el diff antes del merge |
| El hook no funciona en Windows o pide descargar Go | Se detiene y se reporta; O1.4 no avanza sin escaneo local |
| El secreto falso llega a commitearse | Es aleatorio y sin valor, en una rama desechable sin push; se registra como incidente y bloquea O1.3 |
| La protección de `main` admite excepciones | No frena O1.1, pero bloquea O1.3 hasta que Juan decida |
| Los hooks abortan algún commit tras un autoformato | Explicado en el manual; se vuelve a hacer `git add` |
| El manual se vuelve una copia de `CLAUDE.md` | Enlaza en lugar de repetir; se revisa en el diff |
